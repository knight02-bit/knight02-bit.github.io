实现 Harbor 标准的多基准 AI Agent 评测流水线

团队有三个评测基准（SWE-bench Pro / Doc2Repo / Executable2Repo），各自定义不同的 Case 格式，内部评测框架与外部标准不兼容，数据生产和评测执行紧耦合，新增基准或 Agent 需两端同步修改，扩展成本极高。

方案概述

  • 统一交换格式：以 Harbor 标准任务格式作为统一 interchange format，在上游开发 3 个导出适配器，将三大基准的内部 Case 统一转换为 Harbor 目录结构（task + instruction + Dockerfile + solution/ + tests/）。
  • Dockerfile 重写引擎：开发 Dockerfile 工作区重写引擎，通过语句级解析（WORKDIR 跟踪 + 多行续行处理 + 环境变量定位）将 git fetch 步骤替换为 COPY workspace.tar.gz + 解压，支持在线构建与离线自包含构建双模式，配合 (repo, base_commit) 缓存去重与 ownership 归一化。
  • 评分适配层：在下游构建评测适配层，严格移植评分规则 (F2P ∪ P2P) ⊆ passed，并设计统一 test.sh 评分入口（捕获 diff → 重置 base_commit → 应用 patch + 隐藏测试 → run_script → parser → grade），使 Harbor 评分路径与原始 eval.py 按构造等价。
  • 双模式评测：支持 Agent 原生交互与补丁回放重评两种模式：通过自定义 PatchReplayAgent 继承 Harbor BaseAgent 实现，无需修改 Harbor 核心代码；同时为可执行程序评测设计多层防作弊体系（SHA256 哈希比对 + 源码路径扫描 + ELF 文本模式扫描）。

成效

  • 两个系统通过 Harbor 格式完全解耦，形成多种 Agent（Anthropic API / OpenAI API / Claude Code / OpenCode / Codex）的可组合评测矩阵，支持 Oracle 验收、Agent 交互评测、补丁回放对照三种场景。
  • 接入 2000+ 个 GitHub 仓库的实时监控，覆盖 14 种编程语言，Harbor 适配器支持从 pr-watch case 目录一键导出，无需数据格式转换。
  • Oracle 验收通过：cpython 实例 5/5 F2P + 6/6 P2P 全通过（1,671 条测试解析，3.1s 完成），redis 实例 1/1 F2P + 41/41 P2P 全通过（113 条测试解析），评分一致性与 eval.py 完全对齐。
